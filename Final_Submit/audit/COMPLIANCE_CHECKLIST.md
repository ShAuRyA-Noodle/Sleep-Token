### B. ✅ Respect client/server separation

- Client code: [`client/supplymind_client.py`](../../client/supplymind_client.py)
- Server code: [`server/`](../../server/)
- Client never imports server internals — only HTTP API via `httpx`
- Verified by: `grep "from server" client/` returns empty

### C. ✅ Follow Gym-style API

All 5 ops verified by [`tests/test_openenv_compliance.py:98-142`](../../tests/test_openenv_compliance.py#L98-L142):
- `POST /reset` returns initial observation + session_id
- `POST /step` returns next obs + reward + done
- `GET /state` returns current state
- `POST /grader` returns deterministic 0-1 score
- Episode termination guaranteed within `max_steps`

## Reward Design Rules (from hackathon brief)

### F. ✅ Verifier first

[`tests/test_graders.py`](../../tests/test_graders.py) was committed BEFORE training scripts. The grader is programmatic, deterministic (5× same-seed test passes), and does not use an LLM judge for the core reward signal.

### G. ✅ Multiple independent reward components (anti-hacking)

7 components, each independently tested:
1. Revenue preservation (35%) — main signal
2. Stockout prevention (25%) — event-driven, hard to fake
3. Proactive bonus (15%) — time-discounted
4. Cost penalty (10%) — discourages waste
5. Health maintenance (5%) — supply chain health delta
6. SLA compliance (5%) — customer delay reduction
7. Unnecessary action (5%) — penalizes no-effect

### H. ✅ Lock down what the AI can access

- Action validation in [`server/engine/simulation.py`](../../server/engine/simulation.py) — invalid actions rejected gracefully
- Budget tracking with hard cap — can't spend beyond available
- No global state modification possible from action handlers
- Episode termination guaranteed within `max_steps`

### I. ✅ Time and resource limits

- `max_steps = 30 / 45 / 60` per task
- Budget cap per task: $5M / $8M / $10M
- LRU eviction on session pool (max 20 concurrent)
- 10-minute wall-clock kill in autoresearch

### J. ✅ Inspect what AI is generating

- [`tests/test_reward_hacking_adversarial.py`](../../tests/test_reward_hacking_adversarial.py) — 6 attacks tested
- All 6 rejected by **different** layered defenses
- Receipt at [`tests/receipts/adversarial_reward_audit.json`](../../tests/receipts/)

### K. ✅ Curriculum learning

- 3 difficulty levels (easy → medium → hard)
- Autoresearch s3 experiment proved curriculum (40/30/30) gives +0.0967 CI95 lift
- [`ShAuRyA_Phoenix/autoresearch_fixed/state.json`](../../ShAuRyA_Phoenix/autoresearch_fixed/state.json)

### L. ✅ Process + outcome supervision

- Per-step dense reward (process)
- Episode-end grader (outcome)
- Time-discounted proactive bonus (acts during warning > acts after)
